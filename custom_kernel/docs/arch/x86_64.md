# x86_64 Architecture in Ainux

This document describes the implementation details for the x86_64 architecture in the Ainux kernel.

## 1. Boot Sequence
Ainux is loaded via the **Multiboot2** protocol. The entry point is located in `src/asm/boot.asm`.

1.  **Stage 1 (32-bit)**: The kernel starts in protected mode. It performs basic hardware checks, sets up a temporary GDT, and initializes a minimal page table.
2.  **Stage 2 (Long Mode Entry)**: The CPU is transitioned into 64-bit Long Mode.
3.  **Stage 3 (Rust Entry)**: Control is passed to the Rust `kmain` function in `src/lib.rs`.

## 2. Memory Layout
The kernel uses a **Higher-Half** memory model.

*   **Physical Address Space**: Directly mapped starting at a fixed offset.
*   **Kernel Code**: Located at `0xFFFFFFFF80000000`.
*   **Heap**: Dynamically allocated using the `linked_list_allocator`.

## 3. Interrupt Handling
Interrupts are managed via the **Interrupt Descriptor Table (IDT)**.

*   **Exceptions**: Handled by custom Rust handlers (e.g., Page Faults, General Protection Faults).
*   **Hardware IRQs**: Managed via the **8259 PIC** (moving towards APIC in v0.3).
*   **System Calls**: Triggered via `int 0x80`.

## 4. SMP (Symmetric Multiprocessing)
Ainux supports multiple CPU cores.
*   The Primary CPU (BSP) wakes up secondary CPUs (APs) using an **AP Trampoline** (`src/asm/ap_trampoline.asm`).
*   Each CPU has its own GDT and stack to ensure isolation.
